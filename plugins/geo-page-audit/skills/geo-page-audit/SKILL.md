# GEO Page Audit

특정 URL이 **AI 답변에 인용될 수 있는 상태인가**를 실측으로 판정하고, 개발팀이 그대로 티켓을 끊을 수 있는 문서로 정리한다.

## 이 스킬이 답하는 질문

"우리 페이지가 AI 검색에 안 나온다"는 호소의 원인은 대개 셋 중 하나다.

1. **못 들어온다** — robots.txt가 AI 봇을 막거나 서버가 차단
2. **읽어도 건질 게 없다** — 텍스트 밀도가 낮고 JSON-LD가 없음
3. **읽었는데 출처를 안 준다** — 사실이 비정형 텍스트라 귀속이 안 됨

셋은 처방이 완전히 다르다. 추측하지 말고 이 스킬로 어느 쪽인지부터 가른다.

## 실행

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/geo-page-audit/scripts/geo_audit.py" <URL>
```

| 옵션 | 용도 |
|---|---|
| `--no-bots` | 봇 UA 실제 요청 생략. 빠른 재확인용 |
| `--json` | 기계 판독용 JSON. 여러 URL 비교·회귀 측정에 사용 |
| `--timeout N` | 요청 타임아웃 (기본 20초) |

표준 라이브러리만 쓴다. 설치·API 키 불필요.

## 점검 항목

| # | 항목 | 판정 기준 |
|---|---|---|
| 1 | AI 크롤러 실제 접근 | 18종 UA로 GET → 상태코드·바이트 |
| 2 | robots.txt | 그룹 파싱 후 봇별 Allow/Disallow 판정 (allowlist 구조 포함) |
| 3 | JSON-LD | 개수·`@type`·파싱 오류. 인용 가치가 큰 타입인지 |
| 4 | 텍스트 밀도 | 순수 텍스트 / HTML 바이트. **1.0% 미만이면 지적** |
| 5 | head 신호 | title·description·canonical·h1·robots meta |
| 6 | 이미지로만 존재하는 정보 | `<dt>라벨</dt><dd><img></dd>` 형태 탐지 |
| 7 | 한글 인명 공백 | `이 동욱` 형태. 성씨 화이트리스트로 오탐 억제 |
| 8 | URL 시맨틱 | UUID·숫자 ID만 있고 슬러그가 없는 경우 |
| 9 | 렌더 의존도 | 빈 root div·본문 부재로 CSR 셸 추정 |

## 작업 순서

### 1단계 — 실측

URL을 받으면 먼저 스크립트를 돌린다. **추측으로 진단하지 않는다.**

결과의 `지적 사항` 블록이 1차 판정이다. CRITICAL이 없으면 그 페이지의 GEO 기반은 정상이며, 문제는 콘텐츠 경쟁력이나 외부 링크 쪽일 가능성이 크다.

### 2단계 — 근거 보강

스크립트가 잡은 지적을 원본 HTML에서 눈으로 확인한다. 특히 다음은 반드시 실물을 본다.

- **이미지로만 존재하는 정보** → 해당 `<dd>` 원본 마크업을 잘라 확인
- **인명 공백** → CSS 렌더링 문제인지 원본 데이터인지 구분 (`<span>` 안을 본다)
- **텍스트 밀도** → 낮은 원인이 클래스 문자열인지 JS 페이로드인지

HTML은 개행이 거의 없는 경우가 많다. `grep -A` 대신 문자열 오프셋으로 잘라 본다.

```bash
curl -sL -A "Mozilla/5.0 (compatible; Googlebot/2.1)" "$URL" | python3 -c "
import sys; h=sys.stdin.read(); i=h.find('찾을라벨')
print(h[i:i+500] if i>0 else 'not found')"
```

### 3단계 — 인용 현황 실측 (선택)

"실제로 인용이 안 되고 있는가"를 확인하려면 대상 주제를 웹 검색해 상위 결과에 해당 도메인이 있는지 본다. 자사 페이지 대신 위키·커뮤니티가 상위를 차지하면 그 자체가 근거다.

측정 질의는 5개 내외로 고정해 두고 개선 후 재측정한다. 구매·전환과 직결되는 질의(`어디서 살 수 있어`, `어디서 볼 수 있어`)를 반드시 포함한다.

### 4단계 — 문서화

개발팀 전달물은 아래 구조를 따른다. `references/report-template.md`에 전체 골격이 있다.

- **정상 확인 항목을 먼저 분리한다** — "이건 문제 아니다"를 명시해야 논의가 흐려지지 않는다
- 문제마다 `현상(실측값) → 왜 문제인가 → 요구사항 → 수용 기준(DoD)`
- DoD는 **터미널 한 줄로 참/거짓이 갈리는 형태**로 쓴다
- 우선순위는 난이도×효과로 스프린트 편성까지 제안한다

## 판정 시 주의

**차단과 밀도를 혼동하지 않는다.** AI 봇이 200을 받는데도 인용이 안 되면 그건 접근 문제가 아니다. robots.txt만 보고 "차단됐네요"로 끝내면 오진이다.

**`hreflang 0`은 문제가 아닐 수 있다.** HTML `<link>` 대신 sitemap의 `xhtml:link`로 선언하는 사이트가 많다. sitemap을 확인하기 전에는 지적하지 않는다.

**JSON-LD를 넣으라고만 쓰지 않는다.** CSR로 주입하면 브라우저에는 보이지만 크롤러에는 없다. 요구사항에 **SSR 시점 주입**을 명시한다.

**JSON-LD 값과 화면 값이 다르면 스팸 판정 위험이 있다.** 예시를 제공할 때 검증되지 않은 날짜·수치를 임의로 채우지 않는다. 확인 못 한 값은 "CMS에서 채울 것"으로 남긴다.

**순차 공개 콘텐츠의 개수를 하드코딩하지 않는다.** 에피소드·회차·재고 수량은 시점 의존값이다. 현재 공개분임을 주석으로 남기고 동적 산출을 요구한다.

## robots.txt allowlist 구조

전면 차단 후 이름으로만 허용하는 사이트가 늘고 있다.

```
User-agent: *
Disallow: /

User-agent: GPTBot
User-agent: ClaudeBot
...
Allow: /
```

크롤러는 **자기 이름과 매칭되는 그룹 하나만** 따르고, 이름 매칭이 실패할 때만 `*`를 폴백으로 쓴다. 따라서 목록에 없는 봇은 전부 차단이다.

새 봇을 추가할 때는 반드시 **`Allow: /` 앞에** 넣어야 같은 그룹으로 묶인다. 뒤에 넣으면 그룹이 분리돼 무효다.

학습 데이터 활용 정책상 특정 봇을 의도적으로 뺀 경우가 있으므로, 추가를 권고하기 전에 정책팀 확인을 단서로 단다.
