## 1. 배경: 왜 지금 GEO인가

기존 SEO는 "검색 결과에 링크가 노출되는가"를 다뤘습니다.
GEO가 다루는 것은 **"AI가 답변을 만들 때 우리 페이지를 근거로 인용하는가"** 입니다.

| 구분 | 전통 SEO | GEO |
|---|---|---|
| 소비 주체 | 크롤러 → 랭킹 알고리즘 | LLM 컨텍스트 윈도우 |
| 승부처 | 키워드·백링크·CWV | 정보 밀도 · 사실 추출 가능성 · 귀속 근거 |
| JSON-LD 역할 | 리치 스니펫(표시 효과) | 사실 귀속(attribution)의 신뢰 근거 |
| 실패 양상 | 순위 하락 | 답변에는 쓰이되 출처는 남이 가져감 |

## 부록 A. {{Type}} JSON-LD 구현 예시

> 실측 데이터로 작성합니다. 그대로 검증기에 넣어 확인 가능해야 합니다.
> 실제 구현 시에는 하드코딩이 아니라 **CMS 데이터에서 자동 생성**해야 합니다.
> 확인하지 못한 값은 넣지 말고 "CMS에서 채울 것"으로 남깁니다.

```html
<script type="application/ld+json">
{{검증기 통과를 확인한 JSON-LD}}
</script>
```

### 구현 시 주의사항

| 항목 | 내용 |
|---|---|
| 삽입 시점 | **SSR**. CSR로 주입하면 다수 AI 크롤러가 인식하지 못합니다 |
| 시점 의존값 | 회차·수량은 공개분 기준 **동적 산출**. 하드코딩 금지 |
| 데이터 정합 | JSON-LD 값과 화면 표시 값이 불일치하면 **스팸 판정** 위험 |
| 로케일 | `name`·`description`·`inLanguage`를 로케일별로 분기 |
